# حضوربان | Hozourban

سامانه محلی حضور و غیاب مدارس؛ زیرساخت اولیه پروژه با Flask و SQLite.

## نیازمندی‌ها

- Python 3.11 یا جدیدتر
- pip

## نصب سریع (Windows / PowerShell)

```powershell
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
Copy-Item .env.example .env
```

اگر PowerShell اجرای محیط مجازی را مسدود کرد:

```bat
.venv\Scripts\activate.bat
```

## راه‌اندازی (کاملاً از مرورگر)

دیگر نیازی به اجرای دستی اسکریپت‌های ترمینال نیست.

```powershell
python run.py
```

سپس در مرورگر بروید به:

**http://127.0.0.1:5000/**

- اگر هنوز هیچ کاربری ساخته نشده باشد، صفحهٔ **راه‌اندازی اولیه** باز می‌شود.
- حساب مدیر اصلی را همان‌جا بسازید (نام کامل، نام کاربری، رمز عبور).
- پس از ساخت، به‌طور خودکار وارد داشبورد می‌شوید.
- از دفعات بعد، آدرس `/` شما را به صفحه ورود هدایت می‌کند.

### نکات امنیتی راه‌اندازی

- صفحه `/setup` فقط وقتی در دسترس است که **هیچ کاربری** در دیتابیس وجود نداشته باشد.
- رمز عبور حداقل ۱۲ نویسه الزامی است.
- قبل از استفاده واقعی، مقدار `SECRET_KEY` را در فایل `.env` به یک رشته تصادفی بلند تغییر دهید.

## اسکریپت‌های اختیاری (ترمینال)

اگر ترجیح می‌دهید از ترمینال استفاده کنید، هنوز در دسترس هستند:

```powershell
python scripts/init_db.py
python scripts/create_admin.py
```

## آدرس‌های مهم

| آدرس | توضیح |
|------|--------|
| http://127.0.0.1:5000/ | ورود هوشمند (راه‌اندازی یا لاگین) |
| http://127.0.0.1:5000/setup/ | ویزارد راه‌اندازی (فقط بار اول) |
| http://127.0.0.1:5000/auth/login | صفحه ورود |
| http://127.0.0.1:5000/dashboard | داشبورد (نیاز به ورود) |
| http://127.0.0.1:5000/health | بررسی سلامت سرویس |

## دسترسی از شبکه داخلی

در این مرحله سرور توسعه Flask صرفاً برای تست است. اجرای شبکه‌ای با سرور توسعه یا `debug=True` برای استفاده واقعی توصیه نمی‌شود. پیش از استقرار LAN باید:

1. سرور WSGI مناسب انتخاب شود.
2. میزبان و پورت با تنظیمات کنترل‌شده تعیین شوند.
3. فایروال فقط دسترسی شبکه موردنظر را مجاز کند.
4. `SECRET_KEY` امن تنظیم شود.
5. سیاست HTTPS، پشتیبان‌گیری و بازیابی آزمایش شود.

## مهاجرت دیتابیس

در شروع، `create_all()` به‌صورت خودکار در اولین بازدید اجرا می‌شود. پس از آغاز توسعه مدل‌ها، تغییرات ساختار با Flask-Migrate مدیریت شوند. `create_all()` جایگزین مهاجرت نسخه‌بندی‌شده نیست.

## وضعیت فعلی

این خروجی اسکلت اجرایی اولیه است:

- Flask application factory
- SQLAlchemy و SQLite
- مدل‌های User، Role، Permission و تخصیص نقش
- هش رمز عبور
- ورود و خروج پایه + CSRF
- **راه‌اندازی اولیه کاملاً مرورگر‌محور** (ساخت جداول + حساب مدیر)
- endpoint سلامت
- داشبورد ابتدایی محافظت‌شده پس از ورود

هنوز شامل مدیریت کامل مدارس، سیاست‌های مجوزدهی، ثبت حضور و غیاب، محدودسازی تلاش ورود، گزارش‌ها و API محصولی نیست. این موارد باید پیش از بهره‌برداری واقعی پیاده‌سازی و تست شوند.
